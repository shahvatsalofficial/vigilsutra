high VS-CICD-002: pull_request_target workflow checks out pull-request code

.github/workflows/ci.yml:10

potentialconfidence mediumCWE-829CWE-94

Evidence

ref: ${{ github.event.pull_request.head.sha }}
Why it matters
A workflow triggered by `pull_request_target` runs with repository secrets and a write token. Checking out the PR head and then running its code lets an outside contributor execute code with those privileges.
Fix
Use `pull_request` for untrusted code. If `pull_request_target` is required, do not check out or execute PR-controlled content, and keep permissions minimal.
Verify
Confirm no step after the checkout executes files from the PR head, or remove the head checkout.
May be a false positive when
Workflows that check out the PR head but never build, run or source it (for example, labelling only).

potentialconfidence mediumCWE-78

Evidence

Why it matters
A shell is invoked with an interpolated or concatenated command string (or Python `shell=True`). Untrusted input can inject extra commands.

potentialconfidence mediumCWE-89

Evidence

Why it matters
A SQL statement is assembled from variables instead of bound parameters, which can allow SQL injection when any value is user-controlled.

high VS-CODE-001: Dynamic code execution (eval / new Function / exec)

server.js:7

potentialconfidence mediumCWE-95

Evidence

eval(req.body.expr);
Why it matters
Strings are compiled and executed as code. If any part is attacker-influenced this is remote code execution. This rule matches the call, not the data flow.
Fix
Replace with a data-driven approach (lookup table, JSON.parse, ast.literal_eval). Never pass user input to an evaluator.
Verify
The call is removed or its argument is proven constant; add a test with a malicious input.
May be a false positive when
Constant strings, build tooling, or sandboxed evaluators. Trace the argument to confirm.

Evidence

The Dockerfile never sets a non-root USER, so the final image runs as root by default. A compromise of the app gives root inside the container.

potentialconfidence highCWE-829

Evidence

Why it matters
A third-party action is referenced by a mutable tag or branch. If the tag is moved or the publisher is compromised, the workflow runs attacker-controlled code.
Fix
